# Итоговая проверка Tiny Planner 1.0.4

Проверены исходники, зависимости, логика, браузерные сценарии, мобильная вёрстка, документация и конфигурация публикации. Версия и схема данных не менялись. Публикация, отправка в GitHub и создание тега не выполнялись.

## Найдено и исправлено

| Ошибка | Исправление |
| --- | --- |
| Несколько повторений, перенесённых на один день, давали нагрузку только одного повторения | Каждое активное повторение учитывается отдельно: оценка времени, отсутствие оценки и превышение доступного времени |
| Переоткрытое повторение старой закрытой серии не входило в нагрузку | Используется статус конкретного повторения; остальные закрытые даты не создают нагрузку |
| Программная смена значения поля могла оставлять прежнюю видимую подпись | Добавлено синхронное обновление представления без вызова обработчиков изменения данных; охвачены быстрый ввод, восстановление черновика, бюджет и статус доски |
| Выбор времени мог показывать 09:00 вместо сохранённых часов и минут | Сохранённое значение задаётся до создания представления выбора |
| Открытое меню оставалось видимым после отключения поля | Меню закрывается и освобождает временные обработчики |
| Подбор высоты меню использовал взаимные вызовы отрисовки и позиционирования | Ограниченный цикл максимум на восемь вариантов, без рекурсивной отрисовки |
| Измеритель производительности использовал устаревший макет плагина | Макет обновлён; сценарий на 50 000 заметок завершён |
| Остатки старого интерфейса | Удалены неиспользуемый форматировщик даты и правила удалённого `.tp-task-context`; динамические классы статусов сохранены |
| Устаревшие инструкции | Исправлены версия публикации в INSTALL, README, GUIDE, схема, архитектура и инструкция ручной проверки; описания карточек согласованы с 1.0.4 |

## Проверки

- 262 автоматических теста: 262 прошли, без пропусков.
- 81 браузерный сценарий: 81 прошёл. Необязательные полноразмерные диагностические снимки отключались через `TP_SKIP_SCREENSHOTS=1`; проверки поведения выполнялись.
- 36 сочетаний ширины 320–1440 px, масштаба 85/100/115% и светлого/тёмного режима. Проверены касания, подробности, фильтры, отступы продолжений, редактирование подписки, плавающие списки, выбор года, короткое окно и прокрутка страницы над календарём.
- Отдельная матрица тем: 16 сочетаний, включая Minimal.
- TypeScript с `strict`, `noUnusedLocals`, `noUnusedParameters`; метаданные релиза; побайтовое совпадение main.js со сборкой.
- В графе исполняемых импортов 23 собственных модулей циклов не обнаружено. Подбор размера меню ограничен, сохранение поля не вызывает повторное бизнес-событие. Расчёт повторений сохраняет существующие бюджеты и тесты завершения ошибочных правил в отдельном процессе.
- Зависимости: 0 известных advisories; проверены 61 подпись реестра и 4 attestations. Тест происхождения vendored rrule прошёл. Новые зависимости не добавлены.
- В собственном runtime не найдены сетевые запросы, динамическое исполнение кода, запуск процессов или вставка HTML из заметок. Тест собранного плагина блокирует сеть и разрешает только внешний импорт Obsidian. Признаков бэкдоров не обнаружено; это результат проверки, а не математическое доказательство их отсутствия.

## Телефон и производительность

На проверенных ширинах календарь переключается в датированный список; доступны сенсорные действия и изменение статуса без drag-and-drop. Вложенных областей прокрутки и горизонтального переполнения проверяемых поверхностей нет. Длинные названия доступны через подробности или форму. Навигацию можно свернуть одной кнопкой.

В синтетическом Node/jsdom-наборе: 50 000 заметок, 5 000 задач; медиана индексации около 3,1 с, ограниченной выборки Today около 338 мс. Календарь с 5 000 карточками строил около 140 600 DOM-элементов за 4,7 с. Такой объём остаётся ограничением: календарь сохраняет требование показывать все карточки. Это не замер настоящего телефона; для большого хранилища следует сужать период или фильтр проекта.

## GitHub и Obsidian

Workflows разобраны тестами. Checks выполняется на push/PR с правами чтения; Release — на числовой тег с точным совпадением версии manifest. Действия закреплены SHA. Используются Node 22, lockfile, `npm ci --ignore-scripts`, аудит, проверка происхождения, согласованности сборки и тесты. Оба задания ограничены 20 минутами. Публикуются отдельные main.js, manifest.json, styles.css; повторная публикация обрабатывается без создания дубликата, ошибки доступа не маскируются.

Manifest, package, lockfile и versions.json согласованы: версия 1.0.4, минимум Obsidian 1.7.2, мобильный режим разрешён. Сохранены защита API настроек 1.13 и старый интерфейс настроек, vault API, processFrontMatter, корзина, отсутствие Node/Electron в runtime и сохранение неизвестных полей заметок.

Обязательная структура релиза соответствует [официальной инструкции Obsidian](https://docs.obsidian.md/Plugins/Releasing/Submit%20your%20plugin). При этом [рекомендательный checklist](https://docs.obsidian.md/oo/plugin) советует хранить main.js только в релизах и минимизировать его. Текущий проект сохраняет читаемый сгенерированный main.js в исходниках для строгой проверки соответствия; эта существующая политика не была заменена в рамках поиска багов. Это отклонение от рекомендаций, а не подтверждение полного одобрения сканером.

Фактический GitHub Actions run и официальный автоматический review Obsidian здесь не запускались. Для них нужны отправка исходников и публикация релиза; локальная проверка не подменяет результат этих сервисов. Испытания настоящих Android/iOS, Obsidian 1.7.2 и native pop-out остаются пунктами [ручной проверки](OBSIDIAN-QA.md).

## Дополнение: время в минималистичном виде

Указанное время HH:mm видно перед названием обычной карточки, дедлайна и промежуточной отметки. В раскрытых метаданных оно не дублируется; задачи без времени не получают заглушки. Значение доступно в подписи для экранного диктора, изменения затрагивают только представление. После изменения прошли 263 теста и 36 сочетаний ширины/масштаба/темы с проверкой видимого времени. Подписи зависимостей проверены повторно, известных уязвимостей нет. Приведённые выше 81 браузерный сценарий и отдельные 16 проверок тем относятся к предыдущему полному аудиту.
